# Upstream optimizer preservation

## Failure and required outcome

The postprocessor guard starts too late: upstream swap refinement can introduce
Bearer of the Heavens into Krenko and budget reallocation can sell Goblin Bombardment
or Mystic Remora without proving their functions remain. Small scalar objective
gains are not strategic proof. Preserve useful functions at the stage that proposes
the loss, without commander/card-name blacklists.

## Definition of done for this milestone

1. Independent current/off/preserve controls for swap and rebalance, default current
   until tested. Off does not mutate assignments or credit moves. Invalid controls
   fail. Current behavior remains a recorded comparator.
2. Preserve mode works on an isolated copy and atomically accepts/rejects the whole
   stage. Require a real commander context and validate actual complete before/after
   card multisets, functions, protected identities, count, legality/color and budget.
   Rejected proposals cannot alter input, report accepted gains, or spend hypothetical
   freed money. Unknown effect coverage cannot authorize a cut. Exceptions leave
   caller input unchanged. This first version may decline a mixed safe/unsafe
   proposal entirely; extracting safe subproposals is future work.
3. Record full immutable greedy and pre/post stage cards, proposal cards, effective
   policy, budgets, proofs/rejections and proposed-versus-accepted statistics.
   Score gains must never substitute for this evidence. Preserve failure artifacts.
4. Positive tests permit a genuinely proved effect upgrade; negative tests block
   replacing unknown repeatable draw/outlet functions, overbudget/missing-price and
   missing-context changes. Test protected cards, unknowns, rollback and actual
   optimizer API integration. Existing historical harmful transitions stay rejected.
5. Freeze data/source and run the registered 3x3 grid for Krenko51/p3 and Vivi200/p3
   (18 offline builds), then at most two finalists on Giada150/p3 and Lathril100/p3
   (max4 more). Compare actual stage inputs and full final decks. No forced cards,
   models or production writes. Real model builds follow only if offline results
   show solid useful-function preservation without compensating critical losses.
6. Solid improvement requires retained useful functions in the known cases, no
   unsupported new Bearer admission via protected stages, no unproved accepted cuts,
   passing hard checks, and useful behavior on controls. An all-no-op strategy that
   protects an already-poor initial selection is not general intelligence success.
   Report cumulative greedy→final changes outside the guarded stages separately.
7. Actual Cursor narrow code tasks plus Fable5.1 Medium (if confirmed callable) and
   Opus Medium reviews. Full tests and independent result review. No automatic
   deployment of this experiment; production remains the previously approved build.

## Limits and next alternatives

Complete effect proofs remain intentionally narrow. This is function-preserving
transaction control, not a complete MTG interpreter or proof of winning strength.
Move-level gates, safe subproposal extraction, equal-function budget substitutions,
bounded two-card packages and reachable-turn value models remain explicit next
alternatives. Compare them against current/off/preserve, not only a tuned winner.
